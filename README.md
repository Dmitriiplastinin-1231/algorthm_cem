# Численное моделирование траектории ракеты при морском запуске

## Задача

Оценить боковое смещение траектории ракеты на высоте **10 км** при старте с качающейся
морской платформы (период качки 8 с, амплитуда 2°, задержка системы управления 0.3 с).
Выяснить, можно ли пренебречь этим смещением при выводе спутника на орбиту (допуск ±1 км).

### Пояснение каждой цитаты

---

#### Цитата 1 — с. 64, Гл. 2 «Активный участок», введение к главе

> «Возможна точная постановка вариационных задач, оптимизирующих заданный
> показатель качества [2.1, 2.2], однако **найти решение удаётся только численным
> интегрированием** получающихся сложных краевых задач. Поэтому такие задачи
> решаются с помощью ЭВМ.»

**Почему это обосновывает численное интегрирование:**
Автор констатирует, что даже при точной математической постановке задачи (через
вариационный принцип оптимального управления) получающаяся система уравнений
оказывается «сложной краевой задачей», для которой аналитического решения не
существует. Слово «только» — ключевое: оно исключает любую альтернативу.
Наша задача — активный участок полёта с работающим двигателем, переменной
массой, аэродинамикой и системой управления с задержкой — относится именно к
этому классу. Никакой замкнутой формулы для x(t), y(t), θ(t) нет; единственный
выход — численно проинтегрировать систему ОДУ на каждом временном шаге.

---

#### Цитата 2 — с. 101, § 2.4 «Интегрирование уравнений движения»

> «**Уравнения движения ЛА в общем случае могут быть проинтегрированы только
> численно.** Тем не менее, оказывается полезным рассмотрение некоторых модельных
> задач движения, сравнительно простых и допускающих аналитическое решение.
> Полученные конечные формулы позволяют лучше представить физическую картину
> полёта ЛА и оценить влияние различных факторов, которые приводят к уменьшению
> конечной скорости.»

**Почему это обосновывает численное интегрирование:**
Это — прямое нормативное утверждение из профильного учебника: «в общем случае —
только численно». Далее автор добавляет, что аналитические (модельные) решения
полезны лишь для физической интуиции, но не для расчёта реальной траектории.
Иначе говоря, аналитика — инструмент понимания, а не вычисления. Именно поэтому
`rocket_simulation.py` не использует формулу Циолковского или «идеальную скорость» в
качестве итогового результата, а интегрирует полную систему уравнений движения.

---

#### Цитата 3 — с. 65, § 2.1.1 «Стартовый участок»

> «Исследование движения ЛА на стартовом участке для всех типов пускового
> устройства, **как правило, проводится с помощью ЭВМ**. Численное моделирование
> имеет своей целью определение возмущающих аэродинамических сил и моментов
> от ветра, нахождение реакций в опорных поясах (в случае движения по направляющим),
> уточнение потребных параметров автомата стабилизации, проверку принятых
> конструктивных решений по ЛА и пусковой установке. Так как действие возмущающих
> факторов **является случайным**, то при численном моделировании обычно применяется
> **метод статистических испытаний** (с использованием датчика случайных чисел для
> имитации случайных возмущающих воздействий), который позволяет накопить
> информацию о возможных параметрах движения ЛА на стартовом участке.»

**Почему это обосновывает численное интегрирование:**
Автор прямо говорит: стартовый участок — это именно тот класс задач, где аналитика
невозможна, и стандартом отрасли является численное моделирование на ЭВМ. Причина
— случайный характер возмущающих факторов. Качка платформы в нашей задаче —
это именно случайное начальное возмущение (фаза и амплитуда качки в момент старта
не известны заранее). Единственный способ оценить диапазон последствий — прогнать
цикл численных интегрирований при разных значениях начальной фазы φ₀, что и делает
наш скрипт (36 точек в диапазоне 0°–360°).

---

#### Цитата 4 — с. 108, § 2.4.3 «Интегрирование уравнений движения с помощью ЭВМ»

> «Применение мощных ЭВМ позволило **снять практически все ограничения** на
> порядок систем интегрируемых уравнений, вычислять правые части дифференциальных
> уравнений **любой сложности** и осуществлять интегрирование **с заданной высокой
> точностью**.»

**Почему это обосновывает численное интегрирование:**
Автор объясняет, почему именно численный метод стал стандартом: он снимает
ограничения, которые аналитический подход создаёт по определению. Аналитика
требует упрощений — пренебречь вращением Земли, линеаризовать аэродинамику,
принять тягу постоянной. Численное интегрирование ничего из этого не требует: можно
вычислять правую часть системы ОДУ со всеми нелинейностями на каждом шаге. В
нашей задаче правая часть включает переменную массу m(t), нелинейную аэродинамику
X(V, h, ρ(h)), управляющий момент с задержкой δ(t−τ) — всё это «любая сложность»,
о которой пишет Сихарулидзе.

---

#### Цитата 5 — с. 109, § 2.4.3 «Интегрирование уравнений движения с помощью ЭВМ»

> «При машинном счёте **весьма удобен метод интегрирования Рунге—Кутта** высокого
> порядка (обычно четвёртого порядка). **Выбор шага должен осуществляться
> автоматически**, исходя из заданной точности вычислений и необходимости выполнения
> требуемых по условию задачи операций в определённые моменты времени или при
> достижении фиксированных значений некоторых вычисляемых функций. Это
> обеспечивает экономию машинного времени и требуемую точность расчёта параметров
> активного участка.»

**Почему это обосновывает численное интегрирование:**
Здесь Сихарулидзе не просто констатирует необходимость численного подхода, но и
конкретизирует, **какой именно метод** является правильным выбором для задач
активного участка — Рунге—Кутта с автоматическим выбором шага. Это и есть прямое
методологическое обоснование выбора `scipy.integrate.solve_ivp(method='RK45')` в нашем
коде: RK45 — это именно адаптивный метод Рунге—Кутта 4/5-го порядка, где шаг
выбирается автоматически из условия заданной точности (`rtol=1e-6, atol=1e-8`).
Указание «при достижении фиксированных значений» напрямую описывает механизм
событий (`events`) в `solve_ivp` — в нашем случае это фиксация момента пересечения
высоты y = 10 000 м.

### Вектор состояния (6 переменных)

| Переменная | Обозначение | Единицы |
|---|---|---|
| Горизонтальное смещение | *x* | м |
| Высота | *y* | м |
| Горизонтальная скорость | *V_x* | м/с |
| Вертикальная скорость | *V_y* | м/с |
| Угол тангажа (от вертикали) | *θ* | рад |
| Угловая скорость тангажа | *ω_z* | рад/с |

### Уравнения движения (источники: Сихарулидзе 2015, гл. 1–2; Лебедев–Чернобровкин 1973)

**Поступательное движение:**

```
dV_x/dt = [ P·sin(θ+δ) + F_aero_x ] / m(t)
dV_y/dt = [ P·cos(θ+δ) + F_aero_y ] / m(t) − g
```

**Вращательное движение:**

```
dω_z/dt = ( M_ctrl + M_aero ) / I_z(t)
dθ/dt  = ω_z

M_ctrl = P · L_cg · sin(δ)          — управляющий момент (TVC)
M_aero = −F_N · (L_cp − L_cg)       — аэродинамический момент
```

**Система управления с задержкой τ = 0.3 с (условие задачи; Blakelock 1991 даёт
теоретический аппарат для анализа влияния задержки на устойчивость контура):**

```
δ_cmd(t) = −k_p · θ(t) − k_d · ω_z(t)    — ПД-регулятор
δ_real(t) = δ_cmd(t − τ)                   — реальное отклонение сопла (с задержкой)
```

**Начальные условия (качка платформы, Колесников 2003):**

```
θ(0)   = A · sin(φ₀)                       — начальный наклон
ω_z(0) = A · ω_platform · cos(φ₀)          — начальная угловая скорость
```
где *A* = 2° = 0.0349 рад, *ω_platform* = 2π/8 ≈ 0.785 рад/с, *φ₀* — фаза качки в момент старта.

### Метод интегрирования

Используется **RK45** (`scipy.integrate.solve_ivp`) с шагом max_step = 0.05 с и
точностью rtol=1e-6, atol=1e-8. Метод RK45 описан в: Dormand & Prince (1980),
Journal of Computational and Applied Mathematics, Vol. 6, pp. 19–26.
