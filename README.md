# Численное моделирование траектории ракеты при морском запуске

## Задача

Оценить боковое смещение траектории ракеты на высоте **10 км** при старте с качающейся
морской платформы (период качки 8 с, амплитуда 2°, задержка системы управления 0.3 с).
Выяснить, можно ли пренебречь этим смещением при выводе спутника на орбиту (допуск ±1 км).

интегрирование является правильным и единственно возможным методом для задачи
такого класса. PDF книги приложен к репозиторию.

### Пояснение каждой цитаты и её связь с нашей задачей

**Цитата 1 (с. 64) — «…найти решение удаётся только численным интегрированием…»**

Сихарулидзе указывает, что на активном участке траектории (именно этот участок
рассматривается в нашей задаче — от старта до высоты 10 км) уравнения движения
содержат нелинейные аэродинамические члены, переменную массу ракеты и алгоритм
системы управления. Всё это делает задачу «сложной краевой» — аналитически
неразрешимой. Именно поэтому в `rocket_simulation.py` использован численный метод,
а не попытка получить формулу.

---

**Цитата 2 (с. 101) — «Уравнения движения ЛА в общем случае могут быть проинтегрированы только численно»**

Это прямое, безусловное утверждение из профильного учебника по баллистике.
«Общий случай» — это именно наша ситуация: тяга *P(t)* зависит от времени, масса
*m(t)* убывает по мере выгорания топлива, аэродинамическое сопротивление *X(V, h)*
нелинейно зависит от скорости и высоты, а система управления вводит задержку τ.
Ни одно из этих слагаемых не допускает замены на константу без потери смысла задачи.

---

**Цитата 3 (с. 65) — «…исследование… на стартовом участке… проводится с помощью ЭВМ. Численное моделирование… определение возмущающих сил и моментов… метод статистических испытаний…»**

Сихарулидзе явно описывает именно класс нашей задачи: **стартовый участок** с
**возмущающими факторами** (у нас — качка платформы с амплитудой 2° и периодом 8 с).
Книга рекомендует **метод статистических испытаний** — перебор случайных начальных
условий — что точно соответствует нашему подходу: мы прогоняем цикл из 36 значений
начальной фазы качки φ₀ ∈ [0°, 360°) и ищем наихудший случай.

---

**Цитата 4 (с. 108) — «…снять практически все ограничения на порядок систем… правые части… любой сложности… с заданной высокой точностью»**

Это обоснование применимости ЭВМ-интегрирования в задачах с высоким порядком
системы уравнений. Наш вектор состояния имеет 6 переменных (*x, y, V_x, V_y, θ, ω_z*)
плюс буфер задержки управляющего сигнала. Книга подтверждает: именно для таких
систем численный подход «снимает ограничения» — нет нужды упрощать уравнения
до аналитически интегрируемой формы.

---

**Цитата 5 (с. 109) — «При машинном счёте весьма удобен метод интегрирования Рунге—Кутта… Выбор шага должен осуществляться автоматически…»**

Сихарулидзе прямо рекомендует метод Рунге—Кутта 4-го порядка и **автоматический
выбор шага** — это точно то, что реализовано в нашем коде через
`scipy.integrate.solve_ivp(method='RK45')`. Метод RK45 (Dormand & Prince 1980) — это
адаптивный Рунге—Кутта 4/5-го порядка, то есть в точности соответствует методологии,
описанной в данном разделе. Указание «в определённые моменты времени или при
достижении фиксированных значений» соответствует нашей функции-события
`event_10km`, которая фиксирует пересечение высоты 10 км.

## Реализация: `rocket_simulation.py`

Скрипт реализует **Метод B (численное интегрирование)** из анализа задачи.

### Зависимости

```bash
pip install -r requirements.txt
```

### Запуск

```bash
python3 rocket_simulation.py
```

### Вектор состояния (6 переменных)

| Переменная | Обозначение | Единицы |
|---|---|---|
| Горизонтальное смещение | *x* | м |
| Высота | *y* | м |
| Горизонтальная скорость | *V_x* | м/с |
| Вертикальная скорость | *V_y* | м/с |
| Угол тангажа (от вертикали) | *θ* | рад |
| Угловая скорость тангажа | *ω_z* | рад/с |

### Уравнения движения (источники: Сихарулидзе 2015, гл. 1–2; Лебедев–Чернобровкин 1973)

**Поступательное движение:**

```
dV_x/dt = [ P·sin(θ+δ) + F_aero_x ] / m(t)
dV_y/dt = [ P·cos(θ+δ) + F_aero_y ] / m(t) − g
```

**Вращательное движение:**

```
dω_z/dt = ( M_ctrl + M_aero ) / I_z(t)
dθ/dt  = ω_z

M_ctrl = P · L_cg · sin(δ)          — управляющий момент (TVC)
M_aero = −F_N · (L_cp − L_cg)       — аэродинамический момент
```

**Система управления с задержкой τ = 0.3 с (условие задачи; Blakelock 1991 даёт
теоретический аппарат для анализа влияния задержки на устойчивость контура):**

```
δ_cmd(t) = −k_p · θ(t) − k_d · ω_z(t)    — ПД-регулятор
δ_real(t) = δ_cmd(t − τ)                   — реальное отклонение сопла (с задержкой)
```

**Начальные условия (качка платформы, Колесников 2003):**

```
θ(0)   = A · sin(φ₀)                       — начальный наклон
ω_z(0) = A · ω_platform · cos(φ₀)          — начальная угловая скорость
```
где *A* = 2° = 0.0349 рад, *ω_platform* = 2π/8 ≈ 0.785 рад/с, *φ₀* — фаза качки в момент старта.

### Метод интегрирования

Используется **RK45** (`scipy.integrate.solve_ivp`) с шагом max_step = 0.05 с и
точностью rtol=1e-6, atol=1e-8. Метод RK45 описан в: Dormand & Prince (1980),
Journal of Computational and Applied Mathematics, Vol. 6, pp. 19–26.

## Результаты

| Сценарий | Начальная фаза | Смещение на 10 км |
|---|---|---|
| Максимальная угловая скорость | φ₀ = 0° | ≈ −11 м |
| Максимальный угол наклона | φ₀ = 90° | ≈ +13 м |
| Наихудший случай (sweep 36 точек) | φ₀ ≈ 300° | ≈ ±17 м |

**Вывод:** максимальное боковое смещение траектории на высоте 10 км составляет
**~17 м**, что значительно меньше допуска ±1000 м.
Смещением **можно пренебречь** при выводе спутника на орбиту.
